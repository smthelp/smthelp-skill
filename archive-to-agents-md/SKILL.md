# 非代码归档 → AGENTS.md + 结构化底账

## 何时用

用户让「扫描项目文件夹生成 AGENTS.md」，但目标是**按客户/项目/人名组织的资料堆**，
没有 git、没有 package.json、没有构建脚本。此时**代码项目模板会产出编造的假文件**。

先做定性判断：跑 `ls -1` + 一次受限扩展名普查，确认是不是代码仓库。不是就走本流程。

## 第一步：定性（别跳过）

```bash
cd "<目标目录>"
ls -1 | wc -l                                    # 规模
find . -maxdepth 4 -type f 2>/dev/null | sed 's/.*\.//' | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -30
find . -maxdepth 3 \( -name '.git' -o -name 'package.json' -o -name 'requirements.txt' \
  -o -name '*.py' -o -name '*.sh' -o -name 'Makefile' -o -name 'README*' \) 2>/dev/null | head -20
```

判断厂商/平台：找 2-3 个小的专有格式文件，`strings <f> | head -30` 或 `head -c 400 <f> | strings`
看魔术字与厂商字符串。**必须拿到一行确证文本才下结论**，不靠扩展名猜。

## 第二步：AGENTS.md 章节模板（对归档真正有用的六件事）

代码项目的「技术栈/核心模块/常用命令/开发规范」在这里不存在。改写这 11 节：

| # | 章节 | 要点 |
| --- | --- | --- |
| 0 | 30 秒定位 | 这是什么/不是什么；确证依据（原文引用）；旁支代码工程要标「与业务无关」；合法 vs 禁止用途 |
| 1 | 硬规则 | 只读；禁无 maxdepth 递归；深度 ≤4；必挂 head；单命令 60s；禁循环式 find；macOS 无 timeout |
| 2 | 时间口径 | **mtime 是否可信**（同步工具会刷新）。不可信就只认文件名日期，写死 2-3 种允许的提取模式，**禁裸 4 位年正则** |
| 3 | 工作区地图 | 分类索引替代逐个列举；空目录白名单；大目录体积预警；命名规范「不存在」的证据 |
| 4 | 检索配方 | 8-12 条实测跑通的命令模板 + 反模式清单 |
| 5 | 术语表 | 平台/机型/文件格式/机构/日志 分组；**标出哪些扩展名属于另一体系**（易混淆） |
| 6 | 合规红区 | 敏感客户整体 EXCLUDED；禁对外出现的标识符清单；只计数不读的文件类型；「可反推表述」禁令；边界自检 |
| 7 | 底账字段定义 | 数据源优先级；evidence_level A/B/C；缺项一律写「缺项待确认」 |
| 8 | 已确证数字 | **每条必带口径与来源命令**；A 级证据推出的关键结论 |
| 9 | 已知坑 | 静默截断 / SIGTERM / mtime 污染 / SMB 挂起 / EAGAIN 能力差异 / 二进制空字节 / 误导性命名 |
| 10 | 输出规范 + 变更日志 | 每个数字带口径；禁用词；变更日志表 |

## 第三步：底账抽取（两阶段）

**阶段 1 零读取**（只靠路径，覆盖 60-70%）：
优先找**现成的清单型目录** —— 按「站点/机型 + 序列号」命名的整棵子树，
这种是零推断的黄金数据源，先 `find <该目录> -maxdepth 2 -type d` 全量收走，
再回头扫全卷补漏。序列号的单调梯度往往能推出出厂批次顺序。

**阶段 2 小批量读内容**（10 文件/批，失败即跳过，重试 ≤2）：
先定位高价值文件（`VersionInfo.txt` / `*详情.htm` / 配置头），
`head -c 1400 "<path>" | tr -d '\000'`。用 `grep -iE` 过滤字段能省 80% 输出。

**CSV 必须用脚本生成**，不要手写：
```python
HDR = [...]
R = lambda *a: list(a) + [""] * (len(HDR) - len(a))   # 自动补空，防列错位
with open(out, "w", encoding="utf-8-sig", newline="") as f:  # utf-8-sig 让 Excel 不乱码
    csv.writer(f).writerows([HDR] + rows)
```
生成后必跑一次校验：`Counter(r[evidence_idx] for r in rows)` —— 若出现路径串混进等级列，就是列错位。

## 关键经验

- **先找「现成清单」再扫全卷**。一个按机型+序列号组织的目录，价值高于十次全卷 grep。
- **故障/问题目录名就是标签**，抓包文件名格式统一时，父目录名可直接当故障分类，零解压。
- **OS 代际是设备类归档最硬的替代触发点**：从版本文件读 `Operating System`，
  对照 OS EOL 日期，能得出「机器被操作系统锁死」这类可核对的结论，比「设备老化」有力得多。
- **grep 故障关键词要人工去噪**：如 `obsolete` 会把整个「xx obsolete」站点的子树拉进统计。
- **SMB 卷上产物先写本地盘再 cp 回灌**。整卷掉线时 Bash 工具 cwd 不可访问，`cd /tmp` 绕不过
  （详见 `nas-smb-dedup-quarantine` 技能）。

## 合规（不可协商）

- 归档属于**第三方资产**时，客户名只作内部线索假设，接触前须公开渠道二次验证并留记录。
- 军工/受管制行业客户**整体排除**，只计数不读内容；禁「某国际xx客户」这类可反推表述。
- 设计文件（Gerber/ODB++/BOM/图纸）**只计数不读内容**。
- 现场影像默认 C 级禁用，想用必须先证明能升 A/B，而不是反过来。
- 底账含序列号/路径，**仅内部使用**，CSV 正文与 HTML 都要写明。
