# 中文去 AI 味（SMT 行业版）

## 核心定位

中文 AI 腔有极固定的模式，训练有素的读者一眼看穿。本 skill 做的是**诊断具体病症，然后用真人语言替换**——不是微调，是手术。

相对通用版，本版加了两类行业特有病症（H 类术语病、I 类参数病），并引入文体档位，避免在正式方案里乱加"我"。

---

## Step 0：先定文体档位

| 档位 | 文体 | 口语化上限 | 第一人称 |
|---|---|---|---|
| **甲 正式** | 方案、报价说明、验收标准、对外函件、招投标文件 | 低。规范表达，不口语化 | 用"我方/我们"，不用"我" |
| **乙 商务** | 客户微信、供应商沟通、展会物料、官网中文页 | 中。清晰自然，有专业感 | 可用"我们" |
| **丙 内容** | 公众号、知乎、行业社群、LinkedIn 中文帖 | 高。可有个性和观点 | 建议用，观点需要有人承担 |
| **丁 内部** | 日报、周报、复盘、内部通知 | 中。效率优先，别写作文 | 可用"我" |

## Step 1：全文扫描（只诊断，不修改）

### A 类：万能套话（出现即删）
`总的来说` `综上所述` `值得注意的是` `不难发现` `随着…时代的到来` `在当今社会` `越来越多的人开始` `希望本文能对你有所帮助` `这是一个值得深思的问题` `让我们一起`

### B 类：机械并列（最高频特征）
连续 3 句以上句式完全相同。诊断：任取 5 句，若起始词都是"首先/其次/再次/最后"或"第一/第二/第三"，判定为 B 类。

```
AI：首先，我们需要明确客户需求。其次，我们要制定详细方案。
    再次，我们应当严格执行计划。最后，我们进行总结复盘。

真人：客户需求这一步很多人跳过了，后面反复改方案基本都栽在这。
     方案不需要多精致，能落地的比好看的有用。
```

### C 类：机械过渡词
`不仅如此` `与此同时` `除此之外` `更重要的是` `值得一提的是` `总体而言` `针对这一现象`
改法：直接删掉让两段相邻，或换成具体因果。

### D 类：空洞形容词
过于宏大：`深刻` `显著` `卓越` `非凡` `本质` `内在逻辑`
过度保险：`一定程度上` `某种意义上` `相对来说` `不同程度地`
**规则**：删形容词，补数字/时间/结果。

### E 类：句子节奏机械（优先级最高）
AI 生成文本句长高度均匀（每句 15–25 字）。诊断：任取连续 5 句，若字数差异都在 5 字以内，判定节奏机械。

```
AI：波峰焊设备的选型需要综合考虑多方面因素。
    链速的设定直接影响焊接质量与生产效率。
    合理的温度曲线能够有效减少焊接缺陷的产生。

真人：波峰焊选型，先看链速。
     链速定不下来，后面温区怎么调都是白搭——板子在焊锡面的停留时间才是决定性的。
```

**这是读者说"读着不舒服"却描述不出来的头号原因。修节奏优先于改用词。**

### F 类：空洞升华结尾
`生活就是如此，需要我们不断探索` `愿我们都能找到属于自己的答案` `这不仅仅是一个选择，更是一种态度` `让我们共同努力，迈向更美好的明天`
**直接删掉。** 换成一句具体动作或一个真实问题。

### G 类：视角缺失
AI 倾向用"我们"泛指或回避第一人称。改法是加具体视角与经历。
**例外**：甲档（方案、报价、招投标）不加个人视角，加了反而掉分。

### H 类：术语病（行业特有）
两种反向错误：
1. **硬翻术语**——把 `Feeder` 写成"送料器"、`Nozzle` 写成"喷嘴"、`Pitch` 写成"间距"，导致一线工程师看不懂
2. **术语堆砌不加注释**——中文渠道首次出现时不给中文说明，新人看不懂

正确写法：`Feeder（供料器）` 首次出现给注释，之后直接用 `Feeder`。

### I 类：参数病（行业特有）
把可量化信息写成模糊描述：`效率很高` `速度更快` `稳定性好` `大幅降低成本`。
**规则**：凡是能写数字的地方，必须写数字。写不出来就说明数据没拿到，标注"待补"而不是含糊带过。

## Step 2：打标汇总

```
A类（套话）：X 处
B类（并列）：X 处
C类（过渡）：X 处
D类（空洞形容）：X 处
E类（节奏）：轻微 / 中度 / 严重
F类（升华结尾）：有 / 无
G类（视角缺失）：有 / 无（甲档不适用）
H类（术语）：X 处
I类（参数模糊）：X 处

总体 AI 味程度：轻微 / 中度 / 明显 / 严重
主要问题：[最需要解决的 1–2 类]
```

## Step 3：分块重写

- A 类：直接删，不替换
- B 类：打破并列，改因果/转折/叙事推进
- C 类：删过渡词，重写连接逻辑
- D 类：删形容词，补具体细节
- E 类：重新切句，**主动制造长短对比**（这是最见功力的一步）
- F 类：删掉最后 1–2 段升华，换一句具体的话
- G 类：加具体视角（甲档跳过）
- H 类：术语统一，首次注释
- I 类：补数字，或标"待补"

## Step 4：朗读检查

默读一遍：哪里会自然停顿？哪句像背稿？整体有无快慢起伏？太均匀说明节奏还没修好。

## 输出格式

### 短文（1000 字内）
直接输出修改稿，末尾附：
```
【修改说明】
- [类型] × [X 处]：[典型改法示例]
- [类型] × [X 处]：[典型改法示例]
主要改动方向：[一句话]
```

### 长文（1000 字以上）
先诊断报告，再修改稿（格式同上，加 H/I 两类）。

## Gotchas

1. **不要把甲档正式文档口语化**
   解释：方案和报价说明里出现"其实吧""说白了"会直接失去专业感。去 AI 味不等于去正式感。

2. **不要把 SMT 术语硬翻成中文**
   解释：一线工程师说 Feeder、Pitch、CPH，写成"送料器""间距"反而有距离感。首次注释，之后保留英文。

3. **不要为了自然把参数写模糊**
   解释：`0.8 s/件` 写成"速度很快"是本 skill 最严重的误用。参数宁可生硬，不可含糊。

4. **不要把所有"首先其次"都删掉**
   解释：技术流程确实需要顺序（上板 → 印刷 → 贴装 → 回流 → 检测），保留逻辑必要的，删装饰性的。

5. **原文已经很好时不要大改**
   解释：只有少量 AI 特征就只修问题点。全文重写会把原文里对的具体信息一起改坏。

6. **判断标准**
   改完问自己：这段话如果是一个真的销售工程师当面对客户说的，客户会不会觉得奇怪？会，就继续改。
