# 选题钩子实验室（SMT 外贸）

## 核心定位

技术内容没人读，90% 不是写得不好，是**选题没有刺痛感**。原版"咪蒙选题法"用覆盖面、争议性、获得感三指标筛选题，但它的争议性维度在 B2B 工业领域会误导——我们的读者不需要被煽动，需要被说服。

所以本版把第二个维度换成了**决策相关性**：这个选题是否直接关系客户正在做的采购或改造决策。

---

## 触发场景

- "帮我这个选题想几个角度"
- "这篇内容的标题怎么起"
- "开发信第一句怎么写才不像群发"
- "这个视频前三秒拍什么"
- 内容排期时批量生产选题

---

## Step 1：三指标筛选题

每个选题打分（1–5），**总分 ≥ 10 才值得做，单项 < 3 直接淘汰**：

| 指标 | 判断问题 | 高分特征 |
|---|---|---|
| **覆盖面** | 有多少家工厂正被这个问题困扰？ | 混装线、人工插件、产能爬坡这类普遍问题 |
| **决策相关性** | 这个选题离采购/改造决策有多近？ | 读者看完能立刻判断"我要不要改" |
| **可验证性** | 我们能提供真实参数或工况吗？ | 有我们自己的数据或可公开推演的算账 |

**可验证性是最容易被忽略、也最致命的一项。** 一个覆盖广、相关强但我们没有数据的选题，写出来必然空洞，工程师一眼看穿。

### 淘汰信号

- 选题是"[某工艺]很重要" → 废弃，太抽象
- 选题是"[某设备]的优缺点" → 废弃，没有立场
- 选题是"[A] 与 [B] 都要兼顾" → 废弃，这是回避不是观点
- 我们拿不出任何真实参数 → 废弃或降级为"待补数据"

## Step 2：五个角度来源

按这个顺序试，通常第 2、3 个最能出好选题：

1. **反直觉** — 行业默认做法其实是错的
   > "大多数混装线的瓶颈不在贴片机，在没人算过节拍的 THT 段"

2. **具体化** — 不讲原则，讲一块具体的板
   > "一块 300 mm 的板，10 个异形件，我们逐段算给它看"

3. **算账** — 把技术参数翻译成钱
   > "两个插件工一年的成本，等于半台 S-70LD"

4. **时间位移** — 三年前怎么配，现在为什么不行了
   > "元件越做越小，三年前的吸嘴配置现在撑不住 0.4 mm pitch"

5. **边界揭示** — 什么情况下我们这个方案不划算
   > "异形件占比低于 15% 的线，别上异形插件机"

**第 5 类最反直觉也最有效**——公开说"什么情况别买"，信任度提升最大。

---

## Step 3：按渠道写钩子

同一选题，不同渠道的钩子完全不同。每个选题至少产出 3 个钩子变体。

### 技术文章标题
```
模式：[具体对象] + [反常识判断]
  "Why your SMT line's bottleneck is probably not the pick-and-place"
模式：[数字] + [结果]
  "Two operators per shift: what a manual insertion station really costs"
模式：[问题] + [范围限定]
  "How to size a THT line for mixed-assembly boards"
```
规则：≤ 70 字符（搜索结果不被截断）；含核心关键词；不做悬念党。

### 开发信首句
```
模式：他产线上的一个具体问题
  "If you are running mixed SMT/THT boards, the odd-form station is usually
   where the cycle time disappears."
```
规则：**禁止** `Dear Sir/Madam`、`We are a manufacturer of…`、`We are glad to introduce…`；第一句就要证明你懂他的产线。

### LinkedIn 首句
```
模式：反常识判断 / 现场数字 / 一个让工程师点头的问题
  "Most wave soldering problems get diagnosed in the solder pot. They usually
   start at the exit."
```
规则：不要打招呼；不要"今天想聊聊…"；第一句就是内容。

### 视频前 3 秒
```
模式：画面优先，文字补充
  画面：机器在跑，板子连续下板；字幕：0.8 s per component
  画面：人工插件工位；字幕：2 operators per shift
```
规则：**不要用 Logo 动画开场**；第一个画面必须是机器在动或人在操作。

### 展会主标
```
模式：工艺 + 结果，≤ 12 词
  "Odd-form insertion at 0.8 s per component — with tube feeding included"
```

---

## Step 4：自检

每个钩子过一遍：

- 读完/看完，目标读者会不会想"等等，这个跟我有关"？
- 是否指向核心矛盾，而不是旁枝末节？
- 有没有出现禁用套话（`随着…的发展`、`在当今时代`、`众所周知`）？
- 是否含一个具体对象（板子、参数、人数、秒数），而不是抽象概念？
- 同一个角度在其他渠道会重复吗？

## 输出格式

```
【选题评估】
选题：[…]
覆盖面：[N]/5 —— [依据]
决策相关性：[N]/5 —— [依据]
可验证性：[N]/5 —— [依据，列出我们能提供的数据]
总分：[N] → 做 / 弃

【角度方案】
主角度：[五类来源之一] —— [一句话]
次角度：[可选]
核心矛盾：[读者带着什么问题进来，离开时得到什么]

【钩子变体】
1. 文章标题：[…]（X 字符）
2. 开发信首句：[…]
3. LinkedIn 首句：[…]
4. 视频前 3 秒：[画面 + 字幕]
5. 展会主标：[…]

【数据需求】
- [需要技术部确认的参数]
```

## Gotchas

1. **不要用"争议性"去煽动工程师**
   解释：原版选题法鼓励制造争议。B2B 工业领域里，为吵而吵的选题会被工程师判定为不专业。要的是**判断鲜明**，不是情绪对立。

2. **不要选我们拿不到数据的题**
   解释：可验证性 < 3 的选题，写出来必然是空话。要么先去把数据问到，要么换题。

3. **不要把钩子写成悬念党**
   解释："你绝对想不到的波峰焊真相"这种标题，会让专业读者直接划走。钩子的力量来自**具体**，不来自**神秘**。

4. **不要所有渠道共用一个钩子**
   解释：开发信首句要证明你懂对方的产线，LinkedIn 首句要给判断，视频前 3 秒要给画面。同一句话在三个渠道里都不合适。

5. **不要为了标题好看而夸大参数**
   解释：`0.8 s/件` 写成 `0.5 s/point` 会换来一次点击和永久失信。宁可标题平实。

6. **不要忽略"什么情况不适用"这类角度**
   解释：它覆盖面看似小，但信任转化率最高，且几乎没同行敢写。定期排这类选题。
