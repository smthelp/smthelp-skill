# Product Record Contract

Use one Markdown file per public model/version. Keep claims evidence-bound.

```markdown
# {Model} {Product Name}

- **Product family:** {taxonomy family}
- **Model:** {model}
- **Publication version:** {YYYY-MM-DD or approved revision}
- **Public release status:** {approved / engineering confirmation required}

## Function
{Source-supported function, or selection-level description.}

## Verified Source
- [{title}]({source URL or repository path})

## Public Media
- [Official photo library search]({official host search URL})
- [Machine working video on YouTube]({approved URL})

## Options And Fit
{Only approved options; otherwise say configuration confirmation is required.}

## Product Evaluation
- Product/process route
- PCB and material envelope
- Target output and production shifts
- Existing interfaces, traceability, and bottleneck

## Integration
- **Upstream:** {required handling/process interface}
- **Downstream:** {required handling, inspection, test, or process step}
- **Installation and service:** {site utilities, access, training, spare parts, remote support}

## Publication Boundary
This is a public selection reference, not a quotation or complete specification. Confirm configuration-sensitive specifications, compatibility, commercial terms, and availability with engineering.
```

Do not replace an unavailable specification with sales language. Do not treat an image caption, a template placeholder, or an old presentation as a technical source.
