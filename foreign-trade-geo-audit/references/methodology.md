# GEO 方法论 · 为什么这么评分

> 本文件是评分卡的**理论依据**。改 `scoring-rubric.json` 前先读这里，确保改动符合原理而非拍脑袋。

## 一、GEO 与 SEO 的根本区别

| | SEO | GEO |
|---|---|---|
| 争夺对象 | 搜索结果页的 10 条链接 | AI 答案里的**那一句话** |
| 核心指标 | 关键词排名、点击率 | **提及率**、**引用率**、**实体归对率** |
| 优化单位 | 页面 + 关键词 | **实体 + 证据** |
| 排名依据 | 链接权重、相关性 | **交叉验证**：多个独立信源是否说法一致 |
| 失败模式 | 排不上名（还有第 2 页） | **完全隐形**（AI 根本不知道你存在） |

**一句话**：SEO 是让人点进来，GEO 是让 AI 替你说出来。

## 二、2026 年生成引擎的三段处理逻辑

理解这段，就理解了六维评分卡为什么是这六项：

```
用户提问 → ① RAG 召回 → ② 打分重排 → ③ 交叉验证 → 生成答案
              ↑              ↑              ↑
           A/B 维度       C 维度         D/E 维度
          能不能抓到     内容好不好引    信不信得过
```

### ① RAG 召回（Retrieval）
引擎先从索引里捞出一批候选片段。**关键约束：没有独立 URL 的内容等于不存在。**
- 这一段直接对应 **A 技术地基**：抓取器进不来、sitemap 没提交、页面是 JS 渲染的 → 连候选池都进不去。
- 也对应 **B 结构化数据**：结构化数据是召回阶段的"快车道"，引擎优先采信有 schema 标记的片段。

### ② 打分重排（Reranking）
候选片段按相关性、可读性、可引用性排序。**关键偏好：**
- **可被单独摘出来的句子**（一句话能独立成立，不依赖上下文）
- **带数字的表述**（"2 小时响应" > "快速响应"）
- **问句 + 答案结构**（直接匹配用户的提问形态）
- **有明确主体**（"Southern Machinery 成立于 2011 年" > "我司成立于 2011 年"）
- 这一段对应 **C 内容 AI 友好度**。

### ③ 交叉验证（Cross-validation）
**这是 GEO 最容易被忽视、也最致命的一环。** 引擎在生成答案前会检查：这个说法有没有别的地方也这么说？

2026 年主流引擎的可信度分层（业界通称"可信度分层 2.0"）：
- **单个信源在答案中的占比上限约 8%**
- **需要 ≥3 个相互独立的信源**才能形成稳定引用
- **政府 / 协会 / 权威媒体信源的权重约为自媒体的 25–30 倍**

推论（也是硬上限规则的来源）：

| 规则 | 依据 |
|---|---|
| 独立信源 < 3 → D ≤ 35 | 拿不到交叉验证资格，AI 引用你时无第三方可佐证 |
| NAP 冲突 > 1 或镜像域名 > 1 → E ≤ 40 | 实体消歧失败，AI 无法判断哪个是权威主站 |
| JSON-LD = 0 → B ≤ 25 | 无机器可读实体档案，AI 只能靠正文猜测 |
| 内容新鲜度 > 730 天 → C ≤ 45 | 时间衰减，生成引擎对新鲜度的敏感度远高于传统搜索 |

## 三、E-E-A-T 在 GEO 里的落点

| 层级 | 含义 | 外贸站的典型证据 | 对应维度 |
|---|---|---|---|
| **E** Experience 经验 | 你真的干过 | 成立年份、服务客户数、工程师驻场天数、现场照片 | C |
| **E** Expertise 专业 | 你真的懂 | 参数表、工艺白皮书、选型对比、故障排查手册 | C |
| **A** Authoritativeness 权威 | 别人认你 | 协会会员、行业媒体、第三方评测、百科词条 | **D** |
| **T** Trustworthiness 信任 | 你值得信 | 质保承诺、退款条款、响应时效、认证、NAP 一致 | **E** |

**多数外贸站的错误**：把 100% 的精力花在 Experience（说自己多牛），而 Authority 和 Trust 两项为零。结果就是"内优外虚"。

## 四、实体（Entity）—— GEO 的真正单位

生成引擎不是按"网页"思考的，是按**实体**思考的。一个品牌在引擎里是一张档案卡：

```
实体: Southern Machinery
├─ 法定名: Shenzhen Southern Machinery Sales and Service Co., Ltd.
├─ 别名: SMThelp / smthelp.com
├─ 类型: Organization（制造商）
├─ 成立: 2011-03
├─ 位置: 深圳, 广东, 中国
├─ 主营: SMT 周边设备 / THT 插装机 / 波峰焊
├─ 关键人物: Jason Wu (CEO)
└─ sameAs: [LinkedIn, Facebook, Twitter, YouTube]
```

**三个致命风险：**
1. **档案为空** → AI 只能靠正文猜，猜错概率极高（= B 维度低分）
2. **档案分裂** → 三个域名三份档案，权重被稀释（= E 维度低分）
3. **档案错配** → 被归到同名公司名下，等于给别人做了嫁衣

## 五、为什么"引用来源清单 = 信源缺口地图"

盲测时记录「AI 引用了哪些网址」，这份清单有双重价值：
1. **它是 AI 的信任清单** —— AI 引用谁，说明谁在这个话题上被采信
2. **它是你的待办清单** —— 清单上的每个域名，都是一个可以去布局的信源位

这是 Phase 4 唯一必须产出的东西，比评分本身更重要。

## 六、本方法论的边界（诚实声明）

- 各引擎的具体权重与算法**不公开**，上述数字（8%、≥3、25–30 倍）为业界观测共识与工程实践总结，用于**排序与优先级判断**，不构成精确预测。
- 本 skill 的评分是**相对 readiness（就绪度）**，不是绝对排名预测。
- F 维度（AI 平台认知）必须靠真实盲测补录，**任何推演都不能替代实测**。
