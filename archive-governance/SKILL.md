# 大型档案库安全治理

面向**不可再生的业务档案**（客户库、单据库、合同库）。一次误删的代价远高于整理带来的收益。
本技能的核心不是「删得快」，而是**先证明可以删，再动手**。

## 铁律（不可协商）

1. **先比对，后动手。** 任何「删除重复层 / 合并重复项」动作前，必须做**逐文件比对**（路径 + 大小），
   不是只比文件夹名或文件数。文件数相同 ≠ 内容相同。
2. **走回收站，不走删除。** 全部用 `mv` 移入 `_trash-YYYYMMDD/`，**保留原相对路径结构**。
   绝不 `rm -rf`。回滚 = 改回名字。
3. **版本冲突单独留档。** 同名不同大小的文件，两版都要留，交人工裁决。不要替用户决定哪个是正版。
4. **小批 + 复验。** 每批动作后立即复验命中范围与未受影响部分。
5. **dry-run 先行。** 脚本必须支持 `--dry-run`，先出命中清单给用户确认。
6. **只报告，不动手**（第一轮）。涉及删除/改名，第一轮永远只出清单。

## 标准流程

### 阶段 0：勘察（只读）
```bash
# 单次遍历统计各顶层目录文件量（比逐目录 find 快一个数量级）
find . -type f ! -path "*/@eaDir/*" ! -name "._*" | awk -F/ 'NF>1{print $2}' | sort | uniq -c | sort -rn
```

### 阶段 1：嵌套重复层比对（删除前必做）
逐文件比对，输出「仅内层存在」与「同名不同大小」两张清单。
参考实现要点：
- 遍历内层，算相对路径，检查外层同路径是否存在、大小是否一致
- 分类统计后，把「仅内层存在」里**真正的业务文件**与**同步工具临时文件**分开
  （百度网盘：`clfs.tmpupld*`；百度：`*.baiduyun.uploading.cfg`；这些是垃圾，不抢救）
- 版本冲突文件复制到 `_recon/nested_conflicts/` 并出报告

### 阶段 2：空目录识别（单次遍历，别用嵌套 find）
先收集「所有目录」与「含文件的目录及其全部祖先」，差集即空目录。
⚠️ **区分「用户垃圾空目录」与「软件生成的结构目录」**——后者（如
`<vendor>/Software Backup/<model>/统计记录/2022-08`）删掉可能破坏厂商软件的路径预期，**建议保留**。

### 阶段 3：重复客户合并（并集，不是取大）
合并规则：**保留内容多者为主档，另一份的独有文件并入**（不能直接删小的）。
必须处理三种情况：目标不存在 → 复制；目标存在且同大小 → 跳过；目标存在但不同大小 → 冲突留档。
> 实例教训：某对重复客户，小的一份有 **65 个独有文件**。按「删小的」处理会丢 65 个文件。

### 阶段 4：散落文件归集
- **可确证的**（文件名含客户全称且对应文件夹存在）→ 直接归位
- **编号类无法反查的** → 进 `_待归位/`，**不猜**
- 公司级资产 → `_公司级资产/NN-类别/`
- 内部文件 → `_内部资料/`
- 垃圾（0 字节文件、`~$` Office 锁文件）→ 回收站

### 阶段 5：编号台账
解析文件名中的单据编号（如 `<客户码><YYMMDD><流水>`），产出 xlsx + 客户码索引 sheet。
必须加**停用词表**过滤误抓（`XML/LIST/PARTS/PO/PI/DHL/LLC/...`），否则台账里全是噪声。
客户码→客户文件夹的映射是算法推断，**须交人工确认后才能固化**。

## 踩过的坑（务必先读）

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| **文件名含不间断空格 `\xa0`** | `grep "Odd form"` 返回空，但文件明明在 | 用 `repr()` 打印文件名；匹配前 `.replace("\xa0"," ")` |
| **exFAT 卷拒绝重命名 `.mp4`** | `EPERM: operation not permitted, rename`，加 `dangerouslyDisableSandbox` 也无效 | 这是**卷级限制**不是沙箱。只能提示用户在 Finder 手动删除 |
| **沙箱拦截媒体文件操作** | `shutil.copy2` 抛 `PermissionError: EPERM` | 与上一条区分：先在 `/tmp` 测试同类操作确认是卷还是沙箱 |
| **脚本中途崩溃导致状态不一致** | 前段已执行、后段未执行，且无日志 | 每阶段**单独脚本**；结果 JSON 写入放在最后一步之后；先看是否已有部分产出再重跑 |
| **逐目录 `find` 找空目录** | 被 SIGTERM 杀掉（O(n²)） | 改单次遍历 + 集合差集 |
| **文件数相同误判为重复** | 内外层同为 N 个文件，实际内容有差异 | 必须逐文件比对路径 + 大小 |

## 交付约定

- 治理前：`_backup/YYYYMMDD-治理/` 存清单（根目录清单、空目录清单、重复项清单）
- 治理中：`_recon/` 存比对结果、冲突清单、dry-run 与执行日志（JSON + log）
- 治理后：更新项目 `AGENTS.md`，写「已完成 / 遗留问题」两节，含回滚方法
- 回收站 `_trash-YYYYMMDD/` **不自动删除**，等用户确认后由其自行清理
