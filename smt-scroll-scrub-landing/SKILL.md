# SMT 滚动叙事产品页（Scroll-Scrub Landing）

## 核心定位

消费品用滚动动画卖**情绪**；SMT 设备用滚动动画卖**可理解性**。

海外 EMS 工厂的工艺工程师打开一个设备页，脑子里只有一个问题：**这台机器在我的产线上怎么跑起来的。** 滚动本身不是装饰，它就是这个答案的载体——滚动一格 = 工序推进一步。所以本 skill 与消费品类 scroll 站有 7 处根本差异，见下方「工业设备七条」。

方法骨架源自 Komputer Mechanic 的 scroll-scrub 建站流程：一张参考图做唯一事实源 → 像素级静态重建 → 滚动驱动 Hero 影片 → 同美术方向延伸整页。原文见 [komputermechanic.com/tutorials/scroll-animation-website](https://komputermechanic.com/tutorials/scroll-animation-website)。

**许可边界（务必遵守）**：原站声明其 prompt 与模板可自由用于个人及商业项目，但**禁止转售、重新打包、再分发、再发布**——包括发布到 YouTube、Gumroad、付费课程、Newsletter，以及上传到公开代码仓库。因此本 skill 内的 8 条 prompt **全部是针对 SMT 设备外贸场景的原创改写**，不复制、不转载原文任何一条。需要原文请直接访问上述链接，或订阅其邮件列表免费获取。

## 何时用

- 给 S-7900 / S-7020T / S-70LD / S-WS450 / SUL460 / STF1003 / S-680A 等单机制作高转化产品详情页
- 整线方案页（SMT line / THT line）需要让客户"看懂产线怎么串起来"
- 展会大屏循环页、WhatsApp/开发信里发的单页产品介绍、Alibaba 详情页上方的品牌区
- 官网 Hero 区改版，要求"滚动时机器动起来"

- 纯视频物料 → 用 `smthelp-video-script` / `smthelp-remotion-animation-workflow`

## 工业设备七条（与消费品类 scroll 站的根本差异）

1. **滚动 = 工序，不是特效。** 每一格滚动推进必须对应一个真实工艺动作（上料 / 定位 / 插入 / 折弯 / 焊接 / 出板）。没有工艺含义的"炫技位移"一律删掉——工程师会认为你在掩饰没东西可讲。

2. **剖切与模块展开，不是零件炸开。** 消费品喜欢"产品炸开成零件漫天飞"。工业设备保留"展开"，但换一种讲法：**外壳半透明化，真实模块沿机器自身轴向依次浮出**（送料 / 视觉对位 / 插入或焊接机构 / 折弯 / 出板）。两条硬约束——展开的**模块必须是这台机器真实存在的部件**（照真实产品照片与产品资料核，不许凭空加零件）；部件沿机器自身倾斜轴平移并保持与机身平面平行，**不在屏幕空间里垂直向上飘**。工程师要看的是机构关系，不是特效。

3. **数字必须在画面里落地。** 滚动到某一工序时，对应参数上屏（例：滚动到插入头 → `98 N insertion force`）。参数只能来自 `references/verified-params.md`，未核实的写 `待确认`，**禁止从型号名推测**。

4. **可逆性是功能，不是彩蛋。** 回滚必须逐帧还原。工程师会来回滚动反复确认一个动作——这是他在做技术判断，不是被特效逗乐。实现上必须 `preload="auto"` + 双向 scrub，见 `references/tech-impl.md`。

5. **文字一律真 HTML。** 标题、参数、CTA 绝不能烘进图片：工程买家会复制型号和参数去比对，图片里的文字复制不了，也搜不到。

6. **滚动长度有上限。** 单 Hero 滚动段 ≤ 4 屏（约 400 vh）。超过这个长度，采购经理在第三次滚动前就关页面了。整线方案最多 7 屏（一道工序一屏）。

7. **移动端必须降级。** 海外买家大量在手机上点开 WhatsApp/邮件链接，且展会 wifi 很差。移动端默认静态 Hero + poster，滚动只做文字淡入；桌面端才加载影片。上限见 `references/tech-impl.md` 的性能预算。

## 工作流（8 阶段，逐条执行，不许跳步）

> **通用站立规则**（每个阶段都适用）：一次只做当前阶段，不跑到下一条；网站存在后每次改动**前**先备份到 `backups/<时间戳>/`；任何生成前先报成本；用无头浏览器截图 1920×1080 与参考图并排比对后才能说"完成"；每步结束说明做了什么、在等什么。
>
> **调色与质感**：色调/光影/质感一律**烘进生成的图里**，不要用 CSS 滤镜调。
> **永远保持双击 `index.html` 就能打开**——不要引入服务器、npm、Python 或任何需要安装的东西。

### S4A · Hero 滚动影片 · 480p 草稿

```
/goal 给做好的 Hero 加上滚动驱动的影片：向下滚动推进工序，向上滚动还原。

影片必须从页面当前的样子精确起步。先抓起始帧：把所有 HTML 文字和界面元素隐藏，
只留构图好的场景，以 1920x1080 截图，把这张图上传到生成工具作为 START FRAME。
然后生成影片：约 15 秒、16:9、480p、关音频，START FRAME 用上面那张截图，
prompt 里只描述一个连续的镜头运动。480p 是草稿档：几分钟出片、成本约为全质量的四分之一，
而 scrub 会掩盖大部分画质差异；全质量留到下一条 prompt，我批准运动方式之后再做。

选择符合这台机器的变换方式——本机型用「剖切/模块展开」：机器主体留在原地不动，
外壳半透明化，送料模块、视觉对位模块、插入/焊接机构、折弯/出板模块沿机器自身的轴向依次浮出
（滚动回去则依次收回）。
**分镜必须先查 `references/scroll-narrative-playbook.md`**：按机型套对应的模板，
把每一格的「工序 / 画面 / 上屏参数 / 上屏文案 / 滚动作用」填进 prompt 再生成；
模板里没有的机型，照模板的字段格式自己补一版，不要让 agent 自由发挥。
注意：展开的模块必须是这台机器真实存在的部件，
参照真实产品照片与产品资料，不许凭空加零件。

prompt 里写清这些规则：变换从最开始的几帧就启动，不要静止停顿；
分离的部件沿机器自身的倾斜轴移动，保持与机身平面平行，不要在屏幕空间里垂直向上飘；
主体留在原地，只有镜头和部件在动；一镜到底不切镜，缓慢匀速，曝光锁定，运动模糊最小，
画面内不要出现任何文字；全片调色与起始帧一致；首帧与末帧明显不同。
提交前先预查并报出积分，渲染期间每隔几分钟查一次状态就好，视频可能排队很久。

影片回来后用 ffmpeg 为 scrub 编码：
桌面版 CRF 20，每 8 帧一个关键帧，关闭场景切换关键帧；
移动版上限 720p，每 4 帧一个关键帧；两版都去掉音轨并加 faststart；
poster 从【编码后的】桌面版第一帧导出。

然后接线：把 Hero 包进一条很高的滚动轨道并 pin 住，
把视频时间映射到滚动位置——从第一个滚动像素就开始推进，
在每一帧动画里朝滚动位置缓动逼近（而不是直接赋值），让 scrub 有重量感、滚动一开始运动就跟上。
开头几个百分点的滚动里，把静态 Hero 交叉淡入到影片。
加 3–4 段简短章节文字作为真 HTML，随影片进度依次淡入淡出，
章节名用设计稿自身导航里的分区名（以分镜模板里的工序名为准，命名冲突时工序名优先），
并在对应章节激活时高亮导航项。
尊重 prefers-reduced-motion：完全跳过视频，把章节显示为普通板块。
双击 index.html 依然要能跑，不要服务器。

完成的定义：向下滚动播放变换、向上滚动还原，两个方向都顺；章节按时出现。
然后再起一次 reviewer agent，给它参考图和若干个滚动位置的截图，
确认每一帧的配色、暖度、调色仍与参考图一比一吻合，之后才向我汇报完成。
然后等我批准运动方式，再做更高质量的渲染。
```

### S4B · 全质量升级

```
/goal 把已批准的滚动影片升到全质量。

只有在我批准了 480p 影片的运动方式之后才执行。批准的那一条很关键：
先查生成工具的视频放大器能不能直接把这条批准的片子放大，预查成本并告诉我——
放大能精确保留我批准的镜头运动。如果放大不可用，或者放大结果在原尺寸下发虚、有伪影，
就改用原视频模型以 1080p 和最高码率重跑，起始帧和 prompt 必须与批准的影片完全一致，
并把结果当作一条新 take：先重新核对影片规则（一镜到底、不切镜、缓慢匀速、曝光锁定、画面内无文字）再收。

然后按之前完全相同的 ffmpeg 参数重新编码两版 scrub 片段
（桌面版 CRF 20、每 8 帧关键帧；移动版上限 720p、每 4 帧关键帧；去音轨、faststart），
poster 从新的【编码后】桌面版第一帧重新导出，换掉文件但不改任何代码。
确认正向与反向 scrub 依然顺滑，最后跑一次 reviewer，核对若干滚动位置的截图，
确认除了清晰度之外画面没有任何变化。
```
