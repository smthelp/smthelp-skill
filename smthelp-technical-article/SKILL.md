# 技术长文（SMT 设备外贸）

## 核心定位

不是"写一篇关于波峰焊的文章"，而是找到**只有站在产线旁边的人才能写出来的角度**，然后用工程师能核对的方式写出来。

目标读者不是"电子制造行业从业者"这种模糊人群，而是具体的人：

> 一家做汽车电子的 EMS 工厂的工艺工程师，正在为一条混装线（SMT + THT）的产能爬坡发愁，手上有 JUKI 贴片线和一段人工插件段，想搞清楚瓶颈到底在哪、改造值不值。

**这类读者的识别能力极强**：你写没写过产线，三句话就露馅。所以本文体的第一原则是——**不写自己没把握的工况**。

---

## 触发场景

- "写一篇关于 [工艺/机型] 的技术文章 / 博客"
- "做一份 [某工艺] 的白皮书"
- "把这个客户案例写成一篇应用文章"
- 官网博客、LinkedIn 长文、行业媒体投稿

---

## SM 硬约束

- 术语保留英文：Pick-and-place、Reflow、Wave Soldering、CPH、Gerber、BGA、Pitch、Feeder、Nozzle、Conveyor、Odd-form
- 禁用：最好 / 第一 / 顶级 / 革命性 / 赋能 / 智能高效（无信息量的形容词）
- 整线连带：涉及 S-70LD 必配 STF1003；涉及 S-WS450 必配 SUL460
- 禁止给最终报价；如必须提及成本，给区间并注明取决于工艺选配
- 文章类内容（非方案）**不需要**带强制 CTA 两行，但结尾要有明确的下一步动作

## 工作流

### Step 1：锁定读者与他的具体困境

输出一句话：

```
[具体人群]，正在经历 [具体处境]，希望得到 [具体收获]
```

反例："电子制造行业的从业者，想了解自动化设备" —— 这不是读者，这是市场划分。

### Step 2：角度差异化（最关键）

先列出这个话题**最常见的 3–5 种写法**，再找盲点。外贸设备内容里，烂大街的写法通常是：

- "XX 设备的五大优势"
- "如何选择合适的 XX 设备"
- "XX 工艺的发展趋势"

**四种可用的差异化来源：**

1. **反直觉** — 大家都说瓶颈在贴片机，但混装线上真正的瓶颈往往在 THT 段的人工插件
2. **具体化** — 不讲原则，讲一块具体的板子：300 mm 长、10 个异形件、双面板，逐段算节拍
3. **时间位移** — 三年前这条线怎么配，现在因为元件变化怎么改
4. **跨领域嫁接** — 用产线平衡（Line Balancing）的框架解释为什么单看设备参数选不出配置

**记录角度决策**：写下一句可复查的话——
"我选这个角度，因为 [客户确实存在的具体痛点]，
这篇和同题材文章的本质区别是 [别人讲的是设备参数，这篇讲的是产线结果 / 或其他对立面]"。

> 填不出来就说明角度没定，回到 Step 2 重选，不要硬写。

### Step 3：结构设计

技术长文不适合消费内容的"张力弧线"，用**问题诊断结构**：

```
开篇：一个具体的产线现场（不是行业背景铺垫）
   ↓
问题界定：这个现场里，钱/时间具体漏在哪
   ↓
机理分析：为什么会漏（工艺原理，配参数）
   ↓
方案拆解：怎么解决（配置 + 配套 + 为什么这么配）
   ↓
验证：怎么知道解决了（可核对的指标）
   ↓
边界：什么情况下不适用（这段最能建立信任）
   ↓
下一步动作
```

字数分配（以 2500 字英文 / 4000 字中文为例）：

| 段落 | 占比 | 说明 |
|---|---|---|
| 现场开篇 | 5% | 150 字内建立具体感 |
| 问题界定 | 15% | 把损失量化 |
| 机理分析 | 25% | 最重分量，配参数 |
| 方案拆解 | 25% | 配置与配套关系 |
| 验证指标 | 15% | 可核对的数字 |
| 边界与下一步 | 15% | 什么情况不适用 |

### Step 4：开篇钩子（前 150 字生死线）

**可用模式：**

1. **现场开场** — "A 300 mm board with ten odd-form components arrives at the insertion station. The operator has 8 seconds."
2. **数字冲击** — "Two operators per shift, 250 working days a year. That's the real cost of a manual insertion station."
3. **反常识** — "Most wave soldering problems are diagnosed in the solder pot. They usually start at the exit."
4. **问题挑衅** — "如果你的贴片线跑到 30,000 CPH，为什么整线产出还是上不去？"

**禁止**：`随着电子制造业的快速发展…` `在当今智能制造时代…` `众所周知…`

### Step 5：逐段撰写规则

每段内部结构：**论点 → 证据（参数/工况/案例）→ 分析 → 过渡**

具体性原则（强制执行）：

| 不写 | 写 |
|---|---|
| 效率很高 | 0.8 s/件，替代 2–3 名插件工 |
| 大幅降低成本 | 单班省 2 人，按当地人工成本 X/月，Y 个月回本 |
| 很多客户反馈不错 | 某汽车电子客户改造后 THT 段节拍从 Z 降到 Z' |
| 广泛应用于各行业 | 适用于混装线、中大批量、异形件占比 > 15% 的场景 |

### Step 6：结尾

不是"总结全文"，而是：
- 回应开篇那个具体现场
- 给一个清晰的下一步动作（发 Gerber / 预约视频验厂 / 下载配置清单）
- 留一个真实的开放问题

```
读者带走什么：[一个可立即用的判断或算法，不是"了解"]

结构草案（标注字数区间，中文按 / 英文按 words）：
  开篇：[现场]（中文 200–300 字 / 英文 100–150 words）
  问题界定：[量化损失]（中文 300–400 / 英文 150–200）

  验证：[指标]（中文 300–400 / 英文 150–200）

```

### 正文

标题（主标题 + 可选副标题）、正文（小标题分段）、末尾注明字数与数据来源。

## Gotchas

1. **不要写自己没把握的工况**
   解释：这篇文章的读者天天在产线上。编一个"某客户产能提升 40%"比不写更伤——工程师会当场质疑，采购会连带怀疑所有参数。数据拿不到就写"待补"或改成逻辑推演。

2. **不要写正反合结构**
   解释：前半段说 A 好，后半段说 A 有问题，结尾说要平衡。这是最无聊的结构，不产生任何判断。选一个立场。

3. **不要为凑字数加废话**
   解释：宁可 2000 字干货也不要 4000 字稀释。要扩展就加案例深度和数据，不要重复论点。

4. **不要把文章写成产品说明书**
   解释：读者点进来是想解决产线问题，不是看参数表。产品参数放在"方案拆解"里作为证据出现，不要放在开头。

5. **不要隐去不适用的场景**
   解释：写明"什么情况下这个方案不划算"反而最建立信任。只说好处的文章内容会被工程师直接判定为营销材料。

6. **不要堆术语装专业**
   解释：术语是为了精确，不是为了唬人。一个段落里出现读者不需要的术语，就是噪音。

7. **中英文不要互译**
   解释：英文版写给海外工程师（参数、工况、认证），中文版写给国内读者（成本、交付、协同）。同一题材是两篇文章，不是一篇的翻译。
