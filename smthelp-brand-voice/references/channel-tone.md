# 渠道语气矩阵

同一件事，不同渠道的说法不一样。核心变量是**读者当下的心理距离**：陌生开发信最远，已成交客户最近。

| 渠道 | 读者状态 | 语气 | 长度 | 第一句应该 |
|---|---|---|---|---|
| 冷开发信 / Cold outreach | 不认识我们 | 克制、给价值、不要套近乎 | 80–150 词 | 说一个他产线上的具体问题 |
| 询盘回复 / Inquiry reply | 主动找来，比价中 | 专业、反问拿数据、给确定性 | 150–300 词 | 感谢 + 一句证明你听懂了他的需求 |
| 技术方案 / Proposal | 已确认需求 | 严谨、参数密集、可核对 | 不限 | 直接给配置清单 |
| 报价跟进 / Quotation follow-up | 犹豫期 | 温和、不施压、给新信息 | 60–120 词 | 给一个他没有的新信息，不问"考虑得怎么样" |
| LinkedIn 帖子 | 泛行业浏览 | 有观点、可争论、带具体工况 | 100–200 词 | 一个反常识判断或一个现场问题 |
| 产品落地页 / Landing page | 搜索意图明确 | 参数优先、CTA 明确 | 不限 | 机型 + 核心工艺 + 关键参数 |
| 展会物料 / Exhibition | 30 秒扫一眼 | 一句话说清解决什么 | 1 句主标 + 3 个卖点 | 工艺 + 结果 |
| 视频脚本 / Video script | 刷到，可划走 | 前 3 秒给画面冲击 | 30–90 秒 | 机器在跑的画面，不是 Logo 动画 |

## 中英文不是翻译关系

**中文渠道**（国内社媒、内部汇报、供应商沟通）与**英文渠道**（海外客户、社媒、官网）是两套受众，不要互译：

- 英文版写给海外工程师：参数、工况、ROI、标准认证
- 中文版写给内部与国内伙伴：进度、成本、交付、协同

同一个产品，英文版强调 `0.8 s per component insertion with STF1003 tube feeding`，中文版强调 `替代 2–3 名插件工，含供料器整线方案`。

## 常见语气事故

1. **开发信里写 "Dear Sir/Madam"** → 采购会直接归档。找得到人名就用人名，找不到就用职位 `Dear Production Manager`。
2. **跟进信里写 "Just following up"** → 无信息量，且显得在催。改成给新信息：新案例、交期窗口、参数补充。
3. **LinkedIn 上发参数表** → 没人读。先给观点，参数放评论区或链接里。
4. **中文文案里夹一堆英文缩写不加解释** → 内部汇报时工程师看得懂，发给国内供应商或新人就看不懂。中文渠道首次出现要加中文注释。
